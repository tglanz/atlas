# Planning

Keep open issues in [issues](issues), with a separate document for each agreed problem. Remove an issue when it is resolved rather than maintaining a parallel progress snapshot here.

The [product introduction](abstract.md), [domain](domain.md), [user flows](flows.md), and [functional design](design-spec.md) describe intended behavior. Durable decisions and their trade-offs belong alongside those documents; code, tests and configuration establish implementation details.
